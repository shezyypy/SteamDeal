# SteamSaleBotMVP

Переписанный с нуля MVP на основе разбора старого `TelegramBot` (тот проект не тронут,
лежит рядом). Что изменилось по сути и почему — см. раздел "Что исправлено" ниже.

## Возможности

- 🔍 Добавление игры по названию, ссылке на Steam или ID — `/watcher`
- ⭐ Импорт всего вишлиста Steam разом, без добавления игр по одной — `/import_wishlist`
- 👥 Работа в группах/супергруппах — список отслеживания общий на весь чат, а не на человека
- 💎 Premium за Telegram Stars:
  - ♾ безлимитный список игр (бесплатно — до `FREE_GAME_LIMIT`, по умолчанию 15)
  - 🚀 ускоренная проверка скидок
  - 🎚 свой порог скидки (`/threshold`) — не уведомлять о мелких распродажах
  - 🏆 алерт «исторический минимум цены»
  - 🌍 свой регион/валюта цен (`/region`)
  - 📈 история скидок по игре (`/history`)
  - 📊 ценовые алерты по предметам Steam Market — скины/кейсы/карточки (`/track_item`)
- 🔗 Названия игр и предметов в списках и уведомлениях — кликабельные ссылки на Steam
- 🔎 Нечёткий поиск игры по названию — если точного совпадения нет, бот предлагает похожие
  варианты кнопками, не заставляя подбирать точный регистр/пунктуацию
- 🛠 Админ-панель прямо в Telegram (`/admin_stats`, `/admin_broadcast`, ручная выдача Premium)
- 📡 Опциональный мониторинг ошибок (Sentry) и heartbeat воркера — видно, если что-то сломалось,
  не дожидаясь жалоб пользователей
- 🎁 Бесплатный пробный Premium на несколько дней, один раз на чат — `/trial`
- 👥 Реферальная программа — `/referral`, награда за первого приглашённого, который реально
  начал пользоваться ботом (не за пустой `/start`)
- 📰 Дайджест топ-скидок среди отслеживаемых игр, опт-ин — `/digest on`, плюс баннер, если
  статистически похоже на начало крупной сезонной распродажи Steam

    base.py                   async engine/session
    repository.py              весь доступ к БД, параметризованные запросы через ORM
    migrations/                Alembic (async): 0001 — база, 0002 — чаты/premium/группы,
                                0003 — лимиты/порог/market, 0004 — шифрование steam_id64,

                                0006 — пробный период/дайджест/рефералы
  services/
    steam_catalog.py           поиск appid по названию/ссылке + нечёткие подсказки (suggest_matches)
    steam_pricing.py            запрос цены/скидки по appid (appdetails)

    rate_limit.py                    общий ограничитель скорости запросов к Steam (не только конкурентности)
    crypto.py                         шифрование/дешифрование (Fernet) для steam_id64
    referral.py                        награда рефереру за первую добавленную игру приглашённого

  middlewares/

    reset_state_on_command.py     не даёт зависшему FSM-состоянию "съесть" следующую команду

  utils/links.py                 кликабельные HTML-ссылки на игру/предмет для сообщений
  handlers/                      start, feedback, tracking, wishlist, premium, market, admin,

worker.py                        отдельный процесс (проверяет скидки и шлёт уведомления по расписанию)

  backup_db.py                     pg_dump со сжатием и ротацией старых бэкапов

Бот и воркер — два независимых процесса. Бот должен мгновенно отвечать на сообщения и
принимать оплату, а опрос Steam API может занимать время и не должен блокировать чат.

## Настройка окружения

1. Скопируй `.env.example` → `.env`.
2. `BOT_TOKEN` — токен из @BotFather.
3. `ADMIN_CHAT_ID` — твой Telegram ID, куда падают фидбеки.
4. `DATABASE_URL` — `postgresql+asyncpg://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:5432/ИМЯ_БД`
   (через Docker — хост `postgres`, локально — `localhost`; см. `sql/bootstrap.sql`
   для создания роли/базы).
5. `REDIS_URL` — опционально: `redis://localhost:6379/0`. Без него FSM живёт в памяти
   процесса и слетает при рестарте — нормально для разработки, не для прода.
6. `STEAM_API_KEY` — **обязателен** (поиск игр и импорт вишлиста без него не работают).
   Получить бесплатно: https://steamcommunity.com/dev/apikey, в "Domain Name" можно
   вписать что угодно.
7. `DATA_ENCRYPTION_KEY` — ключ для шифрования `steam_id64` в БД. Сгенерировать:
   `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
   Без него бот работает, просто не запоминает Steam-профиль между импортами вишлиста.

### Настройка бота в @BotFather для групп

Чтобы `/watcher` без аргумента (с последующим сообщением-названием) работал и в группах,
у бота должен быть выключен privacy mode: `@BotFather` → `/mybots` → выбрать бота →
`Bot Settings` → `Group Privacy` → `Turn off`. Без этого в группах сработает только
однострочный вариант с аргументом сразу в команде: `/watcher Hollow Knight`,
`/import_wishlist https://steamcommunity.com/id/ВАШ_НИК/` — это работает всегда,
независимо от privacy mode.

```bash
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements-dev.txt

alembic upgrade head          # накатить схему БД

# два отдельных терминала:
python main.py
python worker.py
```

## Запуск через Docker

```bash
docker compose up --build
```

Поднимет Postgres, Redis, бота и воркер одной командой. Миграции пока нужно накатывать
вручную (`docker compose exec bot alembic upgrade head`) — автогена в compose нет намеренно,
чтобы не накатывать схему на прод-базу случайно при каждом рестарте контейнера.

## Админ-панель

Обычные команды бота, доступные только чату с `chat_id == ADMIN_CHAT_ID` — без отдельного
веб-сервера/логина, авторизация здесь — сам Telegram (см. `app/handlers/admin.py`):

- `/admin_stats` — сколько чатов (личных/групп), сколько Premium, сколько заблокировали
  бота, сколько игр/market-алертов отслеживается, и главное — **heartbeat воркера**: когда
  каждый из трёх циклов опроса реально запускался в последний раз, с предупреждением, если
  цикл подозрительно давно не выполнялся (возможно, `worker.py` упал).
- `/admin_premium chat_id [дней]` — выдать Premium (то же самое, что `scripts/grant_premium.py`,
  но без доступа к серверу/консоли).
- `/admin_revoke chat_id` — отозвать Premium.
- `/admin_blocked` — список чатов, заблокировавших бота.
- `/admin_broadcast текст` — разослать сообщение всем незаблокировавшим чатам (ограничено
  ~25 сообщений/сек, чтобы не словить flood control от Telegram).
- `/admin_help` — список этих же команд (не отвечает не-админам).

## Рост и вовлечение

- **`/trial`** — бесплатный Premium на `TRIAL_DAYS` дней (по умолчанию 3), один раз на чат
  (`chats.trial_used_at`). Классический приём: конверсия в платящих выше, если человек уже
  попробовал платные функции, а не просто прочитал питч в `/premium`.
- **`/referral`** — работает только в личке (реферальная ссылка привязана к конкретному
  человеку, а не к группе). Deep-link вида `t.me/<bot>?start=ref<chat_id>`; при `/start
  ref<id>` новый чат запоминает, кто его пригласил (`chats.referred_by`). Награда рефереру
  (`+REFERRAL_REWARD_DAYS` дней Premium) выдаётся не за сам факт перехода, а когда
  приглашённый добавит **первую** отслеживаемую игру (`chats.referral_rewarded`) — иначе
  можно было бы накрутить рефералов пустыми `/start` без реального использования бота.
- **`/digest on|off`** — опт-ин (по умолчанию выключен, чтобы не превращать рассылку в спам
  без согласия). Раз в `DIGEST_INTERVAL_HOURS` (по умолчанию сутки) шлёт топ-10 скидок среди
  игр, которые вообще кто-то отслеживает — переиспользует уже собираемые `sale_snapshots`, не
  заводя отдельный обход всего каталога Steam специально под дайджест.
- **Сезонный баннер** ("похоже, началась крупная распродажа") — вшит в дайджест, а не
  отдельная фича: Steam не даёт официального способа узнать даты сезонных распродаж заранее,
  поэтому вместо хрупкого скрейпинга специальной страницы используется статистический сигнал
  — если скидка одновременно у доли отслеживаемых игр не меньше `SEASONAL_ALERT_THRESHOLD`
  (по умолчанию 30%), это уже непохоже на случайное совпадение пары скидок. Повторно не
  напоминает чаще раза в неделю, чтобы не долбить одним и тем же баннером все 2 недели
  распродажи.

## Мониторинг

- **Sentry** (опционально, `SENTRY_DSN` в `.env`) — инициализируется в `main.py`/`worker.py`
  через `app/monitoring.py`. Не пришлось переписывать обработку ошибок по всему коду: Sentry
  по умолчанию подключает интеграцию с `logging` и сама превращает уже существующие
  `logger.exception(...)` (их много по коду) в события — без `SENTRY_DSN` просто ничего не
  происходит, бот работает как раньше.
- **Heartbeat воркера** (таблица `worker_heartbeats`, без Sentry) — см. `/admin_stats` выше.

## Бэкапы

```bash
python scripts/backup_db.py [--keep N]
```

`pg_dump` со сжатием (`gzip`) и таймстампом в имени файла, старые бэкапы (сверх `--keep`,
по умолчанию 7) удаляются автоматически. Файлы кладутся в `backups/` (в `.gitignore` —
это реальные данные пользователей, им не место в git). Требует `pg_dump` в PATH — ставится
вместе с Postgres. Планировать через cron/Планировщик заданий, например раз в сутки.

## Проверка Premium без оплаты

```bash
python scripts/grant_premium.py <chat_id> [дней]     # выдать (chat_id личного чата = свой tg id)
python scripts/grant_premium.py <chat_id> revoke      # отозвать
```

(То же самое теперь можно делать прямо в Telegram через `/admin_premium` — см. "Админ-панель".
Скрипт остаётся полезен, если админ-чат ещё не настроен или бот вообще не запущен.)

Чат должен быть уже известен боту (хотя бы раз написали `/start`). Специально не команда
бота — иначе любой пользователь мог бы выдать Premium себе сам.

## Тесты

```bash

```

Тесты не требуют ни реального токена, ни реальной БД — это чистая логика (парсинг ссылок,
резолв steamid, логика уведомлений на моках).

## Что исправлено по сравнению со старым TelegramBot

- **Сломанный flow добавления игры.** В старом `main.py` использовался общий на всех
  пользователей список `n = []` — при подтверждении добавления игры падал `IndexError`.
  Здесь стейт живёт в `FSMContext`, а сам список отслеживания привязан к чату
  (`chat_id`), а не к глобальной переменной.
- **Рассылка о скидках была закомментирована целиком.** Здесь она реализована и вызывается
  планировщиком в `worker.py`.
- **SQL-инъекция** — старые `DBAdd.py`/`DBDelete.py`/`DBCheckGames.py` собирали SQL f-строками.
  Здесь всё через SQLAlchemy ORM с bind-параметрами.
- **Секреты в коде** — токен и пароль от БД лежали в `Technical/auth_data.py` открытым текстом.
  Здесь — только через `.env`.
- **Блокирующий psycopg2 внутри async-хендлеров** — заменено на `asyncpg`.
- **Selenium-скрапер** — заменён на прямые вызовы Steam Store API.
- **Меньше трения при добавлении игры** — название, ссылка или ID вместо строгого
  точного совпадения регистра; плюс разовый импорт всего вишлиста одной командой.
- **Free-тариф без реального ограничения возможностей был плохим стимулом для Premium** —
  добавлены: лимит списка игр (`FREE_GAME_LIMIT`, по умолчанию 15) на бесплатном тарифе,
  настраиваемый порог скидки, алерт об историческом минимуме цены и отдельная фича для
  трейдеров — ценовые алерты по предметам Steam Market, которых у бесплатного тарифа нет вовсе.

## Известные ограничения

- **Нужен STEAM_API_KEY.** Старый бесплатный `ISteamApps/GetAppList/v2` (без ключа) Valve
  отключил — сервер отвечает 404 "Method 'GetAppList' not found in interface 'ISteamApps'".
  Переписано на `IStoreService/GetAppList/v1`, а этот метод уже требует ключ. Аналогично
  старый AJAX-эндпоинт вишлиста `/wishlist/profiles/<id>/wishlistdata/` тоже убран —
  используется `IWishlistService/GetWishlist/v1` (этот, наоборот, ключа не требует).
- **API вишлиста не различает "пусто" и "приватно".** И для несуществующего, и для
  приватного, и для по-настоящему пустого вишлиста Steam возвращает одинаковый пустой
  ответ — пользователю показываем обе причины сразу, точнее сообщить не получится.
- **Батчинг appdetails.** `app/services/steam_pricing.py` запрашивает `appdetails` по одному
  appid за раз — пачки через запятую (`?appids=1,2,3`) недокументированы и ненадёжны на
  больших объёмах (см. разбор `Goodparser/test3.py`). Если понадобится сканировать весь
  каталог скидок (а не только отслеживаемые игры), это стоит перепроверить отдельно.
- **Steam Community Market жёстко лимитирует запросы** (заметно строже, чем store-api) —
  поэтому `/track_item` работает только для Premium, опрашивается реже (по умолчанию раз в
  5 минут, `MARKET_POLL_INTERVAL_MINUTES`) и проходит через отдельный, более консервативный
  `RateLimiter` (`STEAM_MARKET_RATE_LIMIT_PER_MINUTE`). Valve не публикует официальные цифры
  лимитов — значения в `.env.example` подобраны по опыту сообщества, а не документации, и
  их стоит уменьшить при первых признаках 429.
- **Ценовые алерты по предметам — одноразовые.** В отличие от игр (уведомление на каждый
  новый уровень скидки), алерт по предмету срабатывает один раз и удаляется — это ближе к
  логике лимитной заявки трейдера, чем к повторяющейся подписке.
- **Оплата Stars не протестирована вживую.** Код `send_invoice`/`pre_checkout_query`/
  `successful_payment` написан по документированному Bot API (валюта `XTR`, без
  `provider_token`), но реальный платёж можно проверить только в живом Telegram —
  локально это не симулируется.
- **Каналы (channel) не поддержаны как полноценный чат.** Группы и супергруппы работают
  полностью; в каналах читатели не пишут команды боту напрямую (только админы каналов
  через `channel_post`) — это отдельный сценарий, не реализованный в этом MVP.

## Безопасность

Что уже сделано в коде:

- **SQL-инъекция исключена архитектурно** — везде SQLAlchemy ORM с bind-параметрами, ни
  одного f-string внутри SQL.
- **Секреты только в `.env`** (не в git), Postgres-роль `steam_bot` не суперпользователь.
- **Экранирование пользовательского текста** (`html.escape`) везде, где имя игры/предмета
  (потенциально введённое пользователем, а не только резолвленное из каталога Steam)
  попадает в HTML-сообщение — иначе можно было бы испортить разметку или вставить
  обманчивую кликабельную ссылку.
- **Анти-спам троттлинг** (`app/middlewares/throttling.py`) — не больше одного апдейта от
  чата за `THROTTLE_INTERVAL_SECONDS`. Это не про UX, а про то, что один недобросовестный
  чат не должен иметь возможность через цикл `/watcher` или `/track_item` нагрузить наши
  исходящие запросы к Steam без предела.
- **Ограничение скорости исходящих запросов к Steam** (`app/services/rate_limit.py`) —
  общий на процесс лимит запросов/минуту к appdetails и Market, независимо от того, сколько
  игр/предметов отслеживается. Это защита самого бота от бана IP, а не пользователей друг
  от друга.
- **Оплата Stars валидируется по формату payload** (`app/handlers/premium.py`) — свой же
  payload, но защита от того, что в будущем появится второй тип платежа и по ошибке
  активирует Premium без проверки.
- **Шифрование `steam_id64` в БД** (`app/services/crypto.py`, Fernet/симметричное) — это
  единственное поле, которое хоть как-то связывает Telegram-аккаунт со Steam-аккаунтом.
  Осознанно не шифровали остальные поля (имена игр, названия чатов, история цен) — это
  либо данные каталога Steam, либо то, что и так уже публично видно в самом Telegram;
  шифровать их — это цена (нельзя быстро искать/индексировать) без реальной пользы.
  Ключ шифрования (`DATA_ENCRYPTION_KEY`) — отдельно от `DATABASE_URL`, по тому же
  принципу, что пароль и ключ от сейфа не должны лежать вместе.
- **Bot API через long polling, не webhook** — у бота нет открытого входящего порта,
  разворачивать reverse-proxy/TLS для приёма апдейтов не нужно, это уже сильно уменьшает
  площадь атаки по сравнению с типичным веб-приложением.

Что нужно сделать тебе самому (это уже не про код, а про эксплуатацию):

- **Не используй пароль из примера (или любой личный/переиспользуемый пароль) для
  боевого сервера.** При деплое на реальный VPS задай сгенерированный уникальный пароль
  Postgres и обнови `DATABASE_URL`.
- **Не открывай порт Postgres (5432) наружу** — он должен быть доступен только с того же
  сервера, где крутятся `main.py`/`worker.py` (в `docker-compose.yml` это по умолчанию так,
  но если разворачиваешь без Docker — проверь firewall).
- **Не логируй и никому не пересылай `BOT_TOKEN`.** Если он всё же засветится (скриншот,
  чужой репозиторий, чат) — сразу `/revoke` в @BotFather.
- **Регулярно обновляй зависимости** (`pip install -U -r requirements.txt` + перепроверка
  тестами) — aiogram/SQLAlchemy/aiohttp иногда закрывают реальные уязвимости.
- **Бэкапь Postgres**, если дело дойдёт до реальных пользователей — `python scripts/backup_db.py`
  по расписанию (см. "Бэкапы" выше), результат стоит копировать на отдельное хранилище,
  не оставлять только на том же диске, что и сама база.
- **`ADMIN_CHAT_ID` — это по сути пароль от админ-панели** (см. "Админ-панель" выше) — тот же
  принцип, что и `BOT_TOKEN`: не логировать, не пересылать, не показывать на стриме/скриншоте.
