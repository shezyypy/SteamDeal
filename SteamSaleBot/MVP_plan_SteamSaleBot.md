## 0. Текущее состояние (кратко)

Сильный, аккуратный код: чистая слоистость (handlers → services → repository → models),
FSM вместо глобальных переменных, все SQL через ORM, миграции Alembic, два процесса
(бот + воркер), heartbeat, Sentry, тесты без внешних зависимостей. Менять можно без страха.

**Точки роста (что реально болит при росте пользователей):**

| Область | Проблема |
|---|---|
| `app/services/notifier.py` | **N+1 запросов** к БД: на каждый сэйл × каждый чат отдельно тянется весь список игр чата, отдельно `already_notified`, `is_chat_premium`, `log_notification` — тысячи мелких round-trip'ов за цикл воркера |
| `app/db/repository.py` (562 строки) | «Божественный модуль»: 40+ функций всех доменов в одном файле |
| имена джоб / heartbeat | Magic-строки `"check_sales_free"` продублированы в `jobs.py`, `market_notifier.py`, `admin.py` — переименуешь в одном месте, тихо разъедется в другом; heartbeat дайджеста пишется, но в `/admin_stats` не показывается |
| `notification_log` | Растёт без ограничений — нет джобы чистильщика |
| 429 от Steam | `fetch_price` молча возвращает `None` при 429, без учёта `Retry-After` |
| нет git | В архиве не было `.git` — рефакторинг без системы отката рискован |

⚠️ **Безопасность (сделать ДО всего):** в расшаренном архиве лежали `.env` (реальные
секреты) и `backups/*.sql.gz` (пользовательские данные). Рекомендация — **сменить/отозвать
BOT_TOKEN и STEAM_API_KEY**, если архив хоть где-то побывал, и никогда не класть эти файлы
в распространяемый архив.

## 2. Блок A — Фиксы и стабильность (код уже прочитан, всё подтверждено)

### A1. Убрать N+1 в воркере (приоритет №1, важно для масштаба)
**Где:** `app/services/notifier.py` + `app/db/repository.py`.
**Что:** сейчас на цикл проверки скидок по региону (N сэйлов × M чатов):
- `list_tracked_games(chat_id)` грузит **весь** список игр чата ради одного имени;
- `already_notified`, `is_chat_premium`, `log_notification`, `mark_chat_blocked` — каждая по
  отдельной транзакции.

**Решение:**
- один батч-запрос «чат → {appid: name}» для всех затронутых чатов;
- один запрос «какие (chat_id, appid, discount) уже уведомлены»;
- один bulk-INSERT `notification_log`;
- набор premium-чатов — один SELECT (а не по-одному в цикле).
Экономия: с ~(N×M×4) запросов до ~5–7 на регион за цикл.

### A2. Единые константы имён джоб/heartbeat
**Где:** `app/scheduler/jobs.py`, `app/services/market_notifier.py`, `app/services/digest.py`, `app/handlers/admin.py`.
**Что:** завести `app/scheduler/job_ids.py` (или константы в одном месте) и использовать везде;
в `/admin_stats` добавить строку heartbeat для дайджеста (сейчас пишется, но не показывается).

### A3. Чистильщик `notification_log`
Раз в сутки удалять записи старше ~30 дней (джоба в `worker.py` + метод в repository).
Иначе таблица растёт навсегда.

### A4. Broadcast: не глотать ошибки молча + Retry-After
- `app/handlers/admin.py::cmd_admin_broadcast`: в `except Exception` логировать текст ошибки
  и не считать сообщения, улетевшие с ошибкой, «разосланными» впустую — но **не** слать пачкой
  через `message.answer` после каждой итерации (это само спамит); копить и отчитаться в конце.
- `app/services/steam_pricing.py::fetch_price`: при 429 спать по `Retry-After`
  (или на N секунд) и сделать одну повторную попытку, а не возвращать `None`.

### A5. Рефакторинг repository.py (после A1–A4)
Разбить 562-строчный файл на доменные модули `app/db/repo/`:
`chats.py`, `games.py`, `market.py`, `digest.py`, `stats.py`, `notifications.py` —
с сохранением единой точки импорта (`app/db/repository.py` реэкспортирует), чтобы хендлеры
не править массово. Это не фича, но сильно упрощает следующие шаги.

## 3. Блок B — Фичи вовлечения (что вернёт пользователя)

**Почему пользователь уходит:** уведомление пришло → на этом цикл завершился. Чтобы человек
возвращался, нужно (1) дать ему повод заглядывать по своей инициативе, (2) сделать так,
чтобы каждый алерт работал на привлечение новых. Идеи ниже — от «дёшево и сразу» к «дороже»:

### B1. 🔘 Кнопки действия в каждом уведомлении *(quick win, виральность)*
Под каждым сообщением о скидке — inline-кнопки:
- «🛒 Открыть в Steam» — `https://store.steampowered.com/app/<appid>/` (уже есть ссылка,
  кнопка просто удобнее);
- **«📤 Отправить другу»** — ссылка `https://t.me/share/url?url=<app>&text=<текст со скидкой>`
  → одно нажатие открывает чат с другом. **Каждый алерт = бесплатная реклама бота.**
- (для группы) «Добавить эту игру в список» — если алерт пришёл не из-за этой игры.

Усилия: S. Код: одна маленькая клавиатура в `notifier.py`/`market_notifier.py`.

### B2. 🎯 Целевая цена на игру («уведоми, когда упадёт ниже N ₽»)
Самая простая и понятная причина **вернуться в бот**: «хочу Hollow Knight ≤ 300 ₽».
- Модель: `target_price_cents` на `TrackedGame` (миграция №0007) + команда `/target номер сумма`
  и кнопка очистки.
- Воркер в `notifier.py`: если `price_final_cents <= target` — отдельное уведомление «🎯 цель
  достигнута!», цель снимается.
- Монетизация: по умолчанию **Premium-фича** (бесплатно — для trial, чтобы пробовать), либо
  «до 3 целей бесплатно» — решите стратегию; рекомендация: премиум, раз уже есть `/threshold`.

### B3. 🔥 `/deals` — «что горит сейчас» по моему списку *(возврат по запросу)*
Сейчас бот только **пушит**. Дать команду, которая **по запросу** показывает живые скидки
среди отслеживаемых игр (актуальная цена, % скидки), с учётом `/region`. Мотивация: «проверю,
не началась ли распродажа» без ожидания пуша. Кнопка «Обновить» на сообщении.

### B4. 💰 Счётчик экономии + персональный отчёт *(якорь удержания)*
Людям нравится цифра «я сэкономил(а)». Считаем из `notification_log` × цены в снэпшоте
(сумма «старой» − «новой» цены на момент уведомления):
- `/stats` — «сэкономлено X ₽, сработало Y уведомлений, самая жирная скидка −75% на Z»;
- встроить строку «за неделю вы сэкономили N ₽» в `/digest`;
- кнопка «Поделиться результатом» с картинкой-карточкой (см. B6).

### B5. 🗑 /list с кнопками удаления и чекбоксами
UX-мелочь, но заметно поднимает впечатление: вместо «/delete 5» — крестики-кнопки рядом
с каждой игрой (или кнопки-номера). Отдельный маленький хендлер callback'ов.

### B6. 📈 График цены PNG в `/history` *(premium-вау, репостится)*
Вместо/вместе с текстовой историей — картинка-график динамики цены
(matplotlib/Plotly→PNG), где видно минимум, текущую цену, сезонные распродажи.
Такое охотно пересылают друзьям → виральность + повод для премиум-оффера.

### B7. 🆓 Оповещение «стала бесплатной / раздача» (post-MVP, осторожно)
Детект в `steam_pricing`/notifier: `initial>0, final==0`. Полезно охотникам за раздачами,
но требует аккуратности с региональными «free» и дедупликацией. Можно отложить.

### B8. 🌐 Inline-режим `@bot <название>` (post-MVP, рост аудитории)
В любом чате набрать `@ИмяБота Hollow Knight` → получить текущую цену/скидку прямо в
сообщении → это бесплатная витрина бота перед новой аудиторией. Нужен BotFather
(/setinline), новый `inline_handler` и кэш каталога (уже есть `steam_catalog`).

### B9. 🔁 Авто-ресинк вишлиста (post-MVP)
Для чатов с сохранённым `steam_id64` — периодическая (раз в сутки-неделю) проверка
вишлиста: новые игры Steam-вишлиста сами добавляются в отслеживание → пользователь
«просто добавляет в Steam» и всё продолжает работать. Сильный удерживающий эффект для
активных пользователей Steam (и повод привязать Steam-профиль).

### Идеи, которые НЕ стоит делать (ваш покорный слуга против)
- «Случайная игра со скидкой»/квесты/ачивки — спам-механика, выжигает пользователя.
- Лидерборды «кто больше сэкономил» в группах — токсично, не в тему.
- Следить за «друзьями» и их покупками — дорого и creepy.

## 6. Метрики успеха (чтобы понять, что сработало)

- Пуш: число чатов, вернувшихся к боту за 7/30 дней (retained chats).
- Уведомления: доставлено/прочитано (хотя бы косвенно — открытия через кнопку «Открыть в Steam»).
- Виральность: переходы по «Отправить другу», число `/start ref*` с реферальных ссылок.
- Premium: конверсия trial → платный, активация новых premium-фич.
- Нагрузка: длительность цикла воркера до/после A1 (видно в логах), число запросов к БД за цикл.
